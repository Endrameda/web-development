Ordered as a path, not a pile. Work top to bottom; only the current phase is active. Everything below it is a map, not a to-do list.

**The cycle every AI feature runs on:** define the task → build the smallest prompt and context that could work → write evals → measure → change one thing (prompt, context, retrieval, model, tools) → measure again. Without evals there is no cycle, just vibes.

**1. How models work (enough to reason about them, not to train them)**

- Tokens: why cost, limits and strange failures are all counted in tokens
- Context windows: what fits, what gets lost in the middle, why more context is not free
- Sampling: temperature and top-p, and why the same prompt gives different answers
- Model tiers: choosing large vs small models on cost, latency and quality
- Hallucination: why it happens, and which techniques reduce it vs only hide it

**2. Prompting and context engineering**

- System prompt vs user prompt: what goes where
- Few-shot examples: when they help, when the model copies them too literally
- Structured output: JSON schemas, and validating what comes back
- Context engineering: deciding what the model sees at each step
- Prompt caching: what it saves and how to structure prompts to hit the cache

**3. Retrieval** — started: [RAG](RAG.md)

- Embeddings: what a vector represents
- Chunking: why it decides retrieval quality
- Vector vs keyword vs hybrid search
- Reranking
- When RAG is the wrong answer: long context, tool calls, fine-tuning

**4. Tools and agents**

- Tool use (function calling): how a model "calls" code it cannot run
- The agent loop: model → tool → result → model, and when to stop
- MCP (Model Context Protocol): one standard for connecting models to tools and data
- Workflows vs agents: a fixed pipeline vs letting the model choose the steps
- Subagents and multi-agent setups: when splitting helps and when it only multiplies cost
- Memory: short-term (context) vs long-term (stored), and how agents keep state

**5. Evaluation**

- Building an eval set from real failures
- Code checks vs LLM-as-judge vs human review
- Regression-testing prompts like code
- Measuring agents on task success, not single responses

**6. Shipping AI features (the frontend edge)**

- Streaming responses into the UI — builds on [Server-Sent Events](../web-platform/Server-Sent%20Events.md)
- Frontend AI SDKs (e.g. Vercel AI SDK): what they abstract and what they hide
- Generative UI: the model choosing components, not just text
- Loading, partial and error states for slow, non-deterministic responses — builds on [Optimistic UI](../frontend-architecture/Optimistic%20UI.md)
- Cost and latency budgets per feature
- Rate limits, retries and fallback between models

**7. Safety and security**

- Prompt injection: any text the model reads is an attack surface
- Data leakage: what never goes into prompts or logs
- Guardrails: input and output filtering, and their limits
- Least privilege for agent tools

**8. Running it in production**

- Observability: tracing prompts, tool calls, tokens and cost
- Versioning prompts and models; surviving model deprecations
- Feeding user feedback back into the eval set

**9. AI in my own workflow**

- Coding agents: delegating well and reviewing the output — builds on [4D framework](4D%20framework%20for%20AI%20Fluency.md)
- When AI makes me faster vs when it lets me skip the learning
- Writing instructions for agents: project context files, skills, reusable prompts
