# MCP

> MCP server is the bridge between you and your database, app, public repository etc. It's also context but lives outside of your codebase. Can connect to them and get additional context for our project, chat or whatever we want to do from the MCP servers.

# When to reach for it
For example our team is uses jira, and there is a ticket(task/issue)  which we should address. We want to get some details of it, and connecting jira MCP server to it. In my personal experience, I just put the link to the jira ticket ClaudeCode asked me to connect to the MCP server. It after while it connected, and I had the tickets description, ACs in my context. and Claude Code know about what have to be done to address this issue

## Gaps — not written yet

- Scopes: local vs project vs user, where each is stored, precedence
- `.mcp.json`: team-shared config, env var expansion, project approval
- Transports: HTTP vs stdio (SSE is deprecated), and when each fits
- Auth: OAuth, fixed callback port, `headersHelper`
- Context cost: tool search and how tool definitions load on demand
- Output limits: warning and max token thresholds, `MAX_MCP_OUTPUT_TOKENS`
- Security: prompt injection from fetched content, trusting a cloned repo's servers
- Permissions and hooks for MCP tools (`mcp__<server>__<tool>` naming)
- Plugins that bundle MCP servers
- Managed MCP config for orgs (allow/deny lists)
- Running Claude Code itself as a server (`claude mcp serve`)
