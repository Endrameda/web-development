# MCP

> An MCP server connects Claude Code to a system outside your repo (Jira, a database, GitHub) by exposing tools Claude can call and resources you can @-mention. Reach for one when the context or the action you need lives somewhere else.

| Note | Answers |
| ---- | ------- |

## When to reach for it

For example our team uses Jira, and there is a ticket (task/issue) we should address. We want its details, so we connect the Jira MCP server. In my personal experience, I put the link to the Jira ticket into Claude Code, it asked me to connect to the MCP server, and after a while it connected. I had the ticket's description and ACs in my context, and Claude Code knew what had to be done to address the issue.

It's not read-only: a server's tools can also write (comment on or transition the ticket), so the same connection that fetches context can change state in the other system.

Not every integration needs one. *(My opinion, not docs.)* If a CLI you already have covers it (`gh`, `psql`), Bash is often simpler than another server. Use MCP when there's no good CLI, when you need OAuth to a hosted service, or when the team should get the same setup from git.

## How

MCP (Model Context Protocol) is the connection between your agent (Claude Code) and an external system where the extra context lives. The server sits on the system's side and exposes:

- **Tools**: actions Claude can call. In Claude Code they are named `mcp__<server>__<tool>`, and that full name is what permission rules and hook matchers use.
- **Resources**: data you reference with `@server:protocol://path`, like `@github:issue://123`. They are fetched and attached when you send the prompt.

The server must be added before Claude can use it. The login window you saw is the OAuth step for a server that is already configured, so with nothing configured Claude has nothing to call. Add one, then authenticate with `/mcp`:

```bash
# remote server (HTTP is the recommended transport)
claude mcp add --transport http notion https://mcp.notion.com/mcp

# local process (stdio). Everything after -- is the server command
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable -- npx -y airtable-mcp-server

claude mcp list     # status of every server
claude mcp get <name>
claude mcp remove <name>
```

Transports:
- **HTTP**: servers hosted by the provider, over the network. Supports OAuth and headers.
- **stdio**: a local process on your machine. Claude Code does not reconnect it automatically.
- **SSE**: deprecated, use HTTP.

Inside a session, `/mcp` shows status, authenticates, reconnects, and enables or disables servers.

#### Scoping Servers
MCP servers can be scoped in three ways:
1. **Local** (default): only you, only the current project. Stored in `~/.claude.json` under the project's path.
2. **User**: only you, available across all projects. Stored in `~/.claude.json`.
3. **Project**: uses a `.mcp.json` file in the project root that you check into version control, so anyone on the codebase gets the exact same servers automatically.

If the same server is defined in several places, the highest precedence wins as a whole entry, with no field merging: local, then project, then user (plugin servers and claude.ai connectors rank below).

A team-shared `.mcp.json` supports env var expansion (`${VAR}` and `${VAR:-default}`) in `command`, `args`, `env`, `url` and `headers`, so secrets stay out of git:

```json
{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": { "Authorization": "Bearer ${API_KEY}" }
    }
  }
}
```

## Gotchas

- **The default scope is local, not project.** `claude mcp add` without `--scope project` does not touch `.mcp.json`, so teammates won't get the server.
- **Project servers need approval.** Interactive sessions ask before using a server from `.mcp.json`; `claude -p`, the Agent SDK and cloud sessions load them without asking. Before approval, `claude mcp list` shows "Pending approval". Reset choices with `claude mcp reset-project-choices`.
- **`--env` swallows the next word.** If the server name comes right after `--env`, the CLI reads it as another `KEY=value`. Put another option between them, as in the example above.
- **Context cost is deferred, not zero.** Tool search is on by default, so only tool names and server instructions load at session start and the full definitions load when Claude needs them. It turns itself off when `ANTHROPIC_BASE_URL` points to a non-first-party host, and then every tool definition loads upfront.
- **Big outputs get cut.** A warning appears above 10,000 tokens, and the default maximum is 25,000 (`MAX_MCP_OUTPUT_TOKENS` raises it). Successful text results over 50,000 characters are saved to a file and Claude gets the path.
- **Fetched content is untrusted.** A Jira ticket body is text someone else can write, and it lands in the context next to tools that can act. Only connect servers you trust, and watch which write tools you auto-approve.
